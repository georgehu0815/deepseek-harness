# Agent Note: MicroDuck 学生学习闭环

Status: proposed

[English](2026-09-05-microduck-student-learning-loop.md) | 中文

## 问题

学生可以编写动作并启动训练，却没有说明预期结果、独立评估策略，或保留下次尝试所依据的证据。将评估放在 Perform 内会模糊训练完成、满足指定仿真标准和获得实体硬件操作授权之间的区别。单个临时报告无法支持跨试验比较，也无法在浏览器刷新后恢复。

[原生 Studio 提案](2026-09-04-microduck-studio.zh.md)继续负责基于模型的编写、不可变物理产物、音频计时、渲染器集成和硬件限制。本提案部分取代其四阶段导航以及仿真与评估共用时长的选择方式，不替换现有提供方、共享播放器或尚未完成的实体运行时工作；两个记录保持有效并互相链接。

[已实现的独立群组决策](../../implemented/feature/2026-09-05-microduck-independent-group-playback.zh.md)增加逐只已保存项目设置和独立策略的同步展示。训练仍通过本学习闭环手动执行；群组回放不提供训练队列、检查点续训或联合策略评估。

## 提案

先交付完整的仿真学习闭环，再增加物理世界编辑、新学习算法或机器人激活。Micro Duck 保留在现有对话栏中 Supply Chain 旁边，Robot Studio 保留在共享可视化栏中。产品文案使用英语，并沿用现有 Harness 外壳、助手、会话所有权和可配置执行提供方。

### 学生流程

[已实现的 Train/Evaluate 布局](../../implemented/simplification/2026-09-05-microduck-train-evaluate-columns.zh.md)取代本提案的五页面导航、Next 页脚及中央 Perform 控件：训练与评估是全宽子标签页，隐藏时保留其内容，目标设置折叠在训练内。下文更广泛的学习与证据要求继续有效；页面名称描述提案中的分组，不代表当前导航。

五个主要阶段为 Choose、Customize、Train、Evaluate 和 Perform。Observe 与 Improve 是 Evaluate 和 Perform 中可用的证据操作，而不是额外的必经阶段。失败评估可直接进入改进实验，无需经过 Perform。

Choose 提供现有九个实验性目标和学习简报：目标、预测、计划改动以及要检查的证据。指导从区分目标与策略、小幅动作、短动作序列和受控比较开始。在真实适配器和测试就绪之前，不将行走、跳跃、世界随机化、示范学习、偏好学习和硬件执行宣传为可用课程。

Customize 保留动作块、全局节拍、主幅度和相对幅度、原创音乐以及高级数值编辑。学生在编写目标旁看到计划改动。外观控制继续明确区别于物理参数。保存动作不等于训练控制器，也不验证动态可行性。

Train 显示学习简报、精确保存的目标、受支持的 CPU/MLX 选项、预算，以及启动试验前选定的评估配方。保存试验会在训练前冻结简报、配方和项目修订；启动试验时另行绑定接纳的运行。训练完成后显示 Evaluate this policy，不标记目标已达成。高级非关联训练继续可用，但不会被事后描述为预先登记的学生试验。

Evaluate 负责策略和报告选择、仿真评估、报告历史、逐回合证据、基线比较及反思。评估保留可测量的直立比例和终止标准，并在有数据时报告跟踪误差。[显式冻结编舞评估](../../implemented/feature/2026-09-05-microduck-frozen-choreography-assessment.zh.md)增加可选的训练前标准及周期与动作块证据；经过校准的通用编舞资格和鲁棒性仍保持未评估状态。每个显示的报告必须匹配其精确策略和导出产物，而非最新草稿或另一运行。评估时域独立于 Perform 的探索性仿真时长。

Perform 负责显式录制仿真与展示。失败或尚未评估的策略仍可用于仿真检查，并显示其状态。硬件保持阻止状态。播放器保留目标与录制的区分、音乐来源、回放计时和不可用测量标签。

### 工作区布局

原生中央面板包含紧凑的项目标题、五阶段进度导航、当前阶段及主要下一步操作。学习和证据区域提供试验历史、比较和反思，不增加第二个永久侧栏。详细设置逐步展开。现有对话输入区保持可见；面板使用其所属组件测量的覆盖布局，在阶段切换时重置局部滚动，同时在编辑时保留滚动位置。

右侧播放器标识来源记录，并说明学生正在观看运动学目标、探索性仿真还是重新仿真的评估回合。它不会把录制姿态表示为实时硬件。评估回合重新生成必须标注为使用保存输入的新仿真，而非原始录制视频。

### 持久记录与所有权

扩展现有 Robot Lab Service Definition、提供方、带类型 Remote Consumer 和模型工具，不增加平行应用服务器。科学计算继续由现有 Python 引擎执行。通过宿主提供方增加有界、不可变、会话所有的学习记录，使学习元数据无需改变 Python 运行时指纹或重新解释现有项目和运行格式。

保存试验会提交学习简报、冻结评估配方、训练输入、保存项目的标识和哈希，以及可选父反思，但不会启动运行。训练该已保存试验时，会在训练器启动或接纳发布之前，提交一个独立的不可变绑定，指向实际准备好的运行。每个试验只能接纳一次运行；客户端遇到结果不明的失败时，应重新加载绑定，而不是自动创建替代运行。进程状态从权威运行派生，而不是保存在第二套生命周期中。准备或绑定持久化失败时，不得启动未跟踪的学习工作。

追加式反思将学生的观察、解释和下一项建议改动绑定到特定试验及精确的已完成评估报告。缺失、跨会话、策略不匹配或被篡改的引用必须被拒绝。已保存反思可以根据父试验的精确项目和训练输入，重新打开明确标注为未保存的改进草稿。保存经检查的草稿会创建引用已提交反思的子试验；不声称反思与子试验原子提交，也不声称未保存草稿已经持久化。可变浏览器选择不是谱系。启动下一试验会创建新运行，不是检查点续训。

提供方通过验证且有界的读取操作公开现有评估历史。未完成的评估接纳不是成功报告。列表和持久解析器在遇到无效数据或配置大小上限时明确失败，而不是伪造空结果或成功结果。产物读写使用配置的文件系统和授权会话存储。

更改课程文本或动作会创建新的实验提议；不得修改先前试验、策略、报告或反思。浏览器刷新重新加载已提交记录，不重放启动操作。store 保存草稿和选择，捕获会话的 LabClient 负责业务快照和请求，框架提供的 hook 将其交给组件。组件不得增加直接服务访问或订阅代码。

### 比较与重新仿真

比较是描述性证据，不是自动胜者评分。显示指定标准、回合数、请求时域、种子、终止次数、直立比例以及可用跟踪误差。只有评估设置、观测语义、冻结物理配置以及已加载的源代码和运行时来源记录均匹配的报告，才能支持同条件评估标签。不同目标、参考动作、预算、学习后端或种子仍作为实验差异显示；多个差异不得被描述为受控的单变量测试。

重新仿真评估回合时，解析保存的报告，验证所属已完成运行的策略字节和运行时兼容性，选择已记录回合种子，并使用报告请求时域及零速度指令。观察到的提前终止步数不是请求时域。该操作仅支持所属运行导出的策略：未改动的 Python loader 无法在执行前根据给定的预期摘要固定预装策略。提供方强制这些输入，UI 不能替换为当前草稿设置。运行时不兼容仍是阻止条件，评估通过不能覆盖它。

### 安全与能力状态

分别表示训练完成、评估结果、缺失测试、运行时兼容性和硬件可用性。不计算通用 Sim2Real 就绪百分比。UI、工具和提供方路径都保持硬件激活不可用。浏览器回放时钟永远不是实体控制器时钟。

当前运行时接受包含 61 个观测和 14 个动作的语义策略配置；维度相同本身不充分。完整的目标特定硬件契约、设置和校准向导、经过认证的权限、本地看门狗、监督批准及独立停止机制，仍是后续硬件版本的前提。MLX 继续使用 Metal 学习器和 CPU 物理；MPS、MJX、BC、DPO 及其他算法在真实提供方存在前保持不可用。

### 实施计划

1. 完成共享试验、反思、评估历史及评估回合请求和结果契约，以及有界验证和会话所有的持久化。宿主编排足够时保留科学运行时文件。
2. 增加预先登记的试验接纳、冻结配方评估、反思持久化，以及基于报告的显式重新仿真。覆盖启动进程前失败、取消和释放、引用完整性、只读拒绝及跨会话隔离。
3. 扩展 LabClient 和声明式草稿及视图 store。实现五阶段、学习简报、评估配方、试验和报告选择、比较，以及基于反思创建改进草稿。保留独立的高级编写和播放器行为。
4. 扩展真实 Loader 和受限原生组装快照。验证保存和重新加载、两个可比试验、失败评估、精确回合重新生成、父关联改进、不匹配证据拒绝及硬件不可用。更新成对所属文档和生成契约。
5. 构建匹配的宿主与客户端产物，并验证端口 3082 上的现有 Robot GUI，仅在必要时重启该获准 GUI。保留监听端口 3081 的进程。真实 CPU/MLX 执行用作集成证据，而非技能已学会的声明。

### 后续版本

物理世界修订和受支持的随机化在仿真反馈闭环之后交付。整理后的数据集、课堂布置与审核，以及更完整的任务和留出测试建立在这些记录上。硬件运行时调查可以独立进行，但实体执行需要自己的经验证适配器和监督验收。新学习算法遵循已验证的数据集和导出要求，而不是作为占位单选按钮出现。

## 考虑过的替代方案

**先增加算法再建立反馈闭环。** 更大的训练菜单不能帮助学生定义成功、解释失败或比较试验。现有 PPO 提供方足以构建学习流程。

**将评估留在 Perform 内。** 这会使评估看起来像可选回放操作，并鼓励把训练完成视为就绪。独立阶段明确证据及其局限，同时保留探索性仿真。

**使用单一 Sim2Real 就绪百分比。** 不相关测试和缺失硬件证据无法诚实地组合成安全批准。分别表示证据和授权状态能够保留其真实含义。

**只在浏览器状态中保存反思，或将其附到以后选中的策略。** 刷新会丢失学习记录，选择漂移可能重新标记证据。必须使用不可变的服务端引用。

**为学习文本重写全部项目和运行格式。** 学习元数据可以作为独立拥有的记录系列，保留现有科学产物。只有产物自身语义变化才需要改变格式；不允许兼容性垫片或重写来源记录。

**将重新仿真显示为原始评估录像。** 当前引擎保存回合结果，不保存帧录制。使用保存输入的重新仿真必须标识为新录制，并继续受运行时兼容性检查约束。

## 验收标准

- 学生可以说明目标和预测、保存目标、以冻结评估标准启动试验，并在训练后进入独立 Evaluate 阶段。
- 试验、报告和反思历史在同一授权会话中刷新后仍存在；其他会话不能通过复制标识符访问它们。
- 失败评估提供精确回合证据，允许明确标记的重新仿真，不会静默更改策略、种子、时域或科学运行时。
- 已保存反思可以显式重新打开未保存的改进草稿。保存并启动经检查的草稿，会保留父记录并产生新试验和运行。比较显示实际差异，并拒绝无依据的同条件结论。
- 目标预览、仿真测量、未评估的完整动作和鲁棒性、训练吞吐量以及被阻止的硬件保留真实标签。
- 专项源码测试、真实 Loader 执行、受限无密钥组装转录及重新构建的浏览器覆盖完整闭环。广泛回放通道不得泄漏到实时模型提供方。

## 风险

长历史列表和大产物需要配置上限及完整响应边界。加载报告历史不得抹除先前选定证据，也不得在会话释放后覆盖较新数据。预先登记标准有意限制学生灵活性：探索性评估可以使用其他标准，但不能冒充试验的原始评估。本版本不纳入物理世界、硬件执行、新算法和检查点续训，以范围宽度换取可验证的学习闭环。
