# Agent Note: 原生 MicroDuck 策略工作室

Status: proposed

[English](2026-09-04-microduck-studio.md) | 中文

## 问题

机器人学习工作区需要一条可复现的路径，将编写的行为连接到训练、确定性评估、仿真回放和部署准备。MicroDuck Lab 提供了实用的 CPU MuJoCo/SB3 引擎和浏览器渲染器，但其独立应用没有 DSH 会话所有权管理，也没有经过验证的硬件发布流程。导出的张量维度本身不能证明兼容性：本地动作片段模仿将身体指令观测索引 59–60 用作相位，而所检查的机器人运行时赋予这些字段不同的含义。

机器人编写需要与对话同宽的控件，同时不能独占地球可视化栏。[slot 标准](../../implemented/architecture/2026-07-22-slot-type-chain-implementation.zh.md)仍然是权威定义；[Terra 集成决策](../../implemented/architecture/2026-08-20-terra-geo-plugin-port.zh.md)保留其地理提供方、投影和渲染依据。本提案负责 MicroDuck 编写与共享播放器集成，不负责地理能力。[学生学习闭环提案](2026-09-05-microduck-student-learning-loop.zh.md)通过独立评估、持久学习试验、比较和反思扩展流程；本文的科学运行时和共享播放器决策仍然适用。

[已实现的独立群组决策](../../implemented/feature/2026-09-05-microduck-independent-group-playback.zh.md)负责逐只策略选择、手动训练设置和同步记录回放。[原生 Clip Gen 决策](../../implemented/feature/2026-09-05-microduck-native-clip-gen.zh.md)负责图形关节与联动编写，以及经过检查的 MP4 参考导出。两者都不替换本提案的科学运行时或延期硬件工作。[空白会话呈现决策](../../implemented/architecture/2026-09-05-blank-session-presentation-views.zh.md)负责不依赖聊天的 View 资格，不代表完成此处更广泛的 Studio 流程。

## 提案

通过可配置的本地提供方复用 Python 仿真、执行器、训练和 ONNX 导出实现。将独立的渲染与动作编写组件移植到原生客户端插件中，并保留上游署名。不启动独立 Next.js 应用，也不让浏览器直接连接可配置的 Lab URL。

Robot Lab Service Definition 负责提供方注册，以及工具和带类型 Remote 调用方共享的公共操作。MicroDuck Service Provider 负责进程监管和不可变产物。工具 Consumer 暴露有界、与任务相关的结果。客户端插件负责中央流程及其共享的右侧播放器。[已实现的 Train/Evaluate 布局](../../implemented/simplification/2026-09-05-microduck-train-evaluate-columns.zh.md)负责全宽中央子标签页、折叠目标设置及中央不提供 Perform 控件；本文更广泛的科学运行时与播放器要求继续有效。所有注册都随 Cordis fiber 释放；不需要修改 agent loop（智能体循环）。

### 原生中央流程与共享播放器

在 `conversation.view` 中以顺序 40 注册 Micro Duck，位于 Supply Chain 旁；Robot Studio 保留在与地球共享的右侧可视化工作区。`visual.workspace.view` 包装组件在没有会话时不访问存储 hooks，随后渲染其声明的会话作用域 `robot-lab.visual.player` 子 slot。两个条目共享固定会话的一个 `LabClient` 和一个 `PlaybackTransport`。客户端对象拥有业务记录与轮询；声明的存储拥有草稿和查看偏好。关闭或隐藏播放器会暂停音频与姿态，但不取消训练。切换会话绝不改变请求目标，迟到响应不能更新已 dispose（资源释放）的持有方。

### 编写目标、项目与音乐

九种原创实验性舞蹈或动作模板使用实际 MJCF 模型的十四关节顺序、默认姿态和限制。保存创建不可变的会话所属格式 2 项目修订，包含配方、模型与配置、解析后的有序动作块、完整组合的训练推荐、编译目标和 SHA-256。可选编写动作块是唯一动作来源，共用 BPM，并保持动作与音乐总拍数一致；每块相对幅度乘以总动作幅度。每个解析后的块冻结其模板元数据。完整动作训练推荐综合所有块，而非只使用首模板。模板、片段和音乐格式保持为 1，运行格式为 3；旧项目格式被拒绝，不迁移。MuJoCo 正向运动学提供真实模型预览，标为 Target preview / Not physics-tested，不虚构物理，也不作为已学习行为的证据。训练准入解析并冻结所选项目修订和音乐；后续草稿编辑不能重命名、改变时序或重新绑定旧记录。

音乐通过本地带种子的原创打击乐、贝斯和旋律合成，风格为 disco、electronic、lofi 和 chiptune，不使用外部账户或密钥、人声或商业录音。只持久化配方；浏览器生成有界的临时 PCM 和可下载 WAV。音乐生成与播放保持为独立的显式操作。有音乐的播放使用 AudioContext 作为声音和姿态的主时钟；显式 `music: null` 使用单调时间。音频失败会暂停并显示原因，绝不静默替换时钟。暂停、跳转、重新开始、结束、隐藏视图或文档、切换会话和 dispose 都同步二者。回放绝不自动开始，也不通过循环短记录来暗示持续表现。每会话的 0.5×、1×、1.5× 和 2× 回放倍速同步缩放逻辑时间及音频速度与音高，不改变保存的 BPM、PCM/WAV、训练或实测身体速度。在音频恢复待完成时改变倍速会取消启动并暂停。冻结的块与拍数指标使用记录时间，训练吞吐量仍与动作速度相互独立。

每个 RobotFrame 按模型实际关节顺序携带遥测：qpos、qvel、延迟后的控制器位置目标、施加的执行器扭矩，以及已识别根部的世界速度、速率和倾角。物理值必须来自仿真状态，而非目标片段或带噪观测。运动学预览值保留目标标签，没有实测扭矩或控制器输出。不记录足部接触。音乐速度、物理移动速度和学习吞吐量是不同量。

### 实验身份与执行

每次运行冻结配方、准确的参考片段、种子、环境和执行器设置、语义观测配置、源代码版本及导出校验和。热启动后继运行还需要冻结父检查点身份；这不属于已交付范围。策略加载器恢复记录的片段，而不是解析行为默认值。产物根目录位于获准工作区内；源代码检出位置属于配置，不是硬编码部署路径。

进程所有者使用子进程和沙箱服务，清除无关凭据，限制输出，并等待终止完成。并发修改和重试启动不得创建重复训练任务。失败、取消和中断恢复必须与成功完成区分。浏览器刷新绝不重放训练启动或硬件指令。

已完成运行将导出字节绑定到冻结的哈希；推理使用已验证的字节，而不是重新打开可修改的路径。实际 BAM 参数值及其来源属于实验来源记录，因为安装的参数包可能在 Lab 检出不变时改变物理行为。每次评估具有独立身份，并在执行之前记录条件和策略哈希；后续评估不得抹去已有证据。运行所有权从准入开始，销毁必须等待进程退出和持久化状态收尾。过期的查询结果不得降低终态运行的状态。

### 可选的 Apple MLX 学习

[已实现的 RLX 后端决策](../../implemented/feature/2026-09-05-microduck-rlx-backend.zh.md)负责单独配置的 `rlx` 学习器及其产物绑定。下文 DSH 自有 `mlx` 决策仍然适用；任一后端都不证明本提案中延期的编舞或硬件验收已完成。

CPU 保持默认。可选的 Apple MLX 后端在 Metal 上执行策略和价值网络学习，同时保留 CPU MuJoCo/BAM 物理仿真。其 DSH 原创 PPO 实现参考 RLX 的思路，但不复制或依赖 RLX 或 EnvPool。独立的冻结配方记录算法和设备选择；它不包含对称损失，与 CPU 训练器不具备数值等价性。对于小规模实验，GPU 开销可能超过学习吞吐量收益，因此不承诺提速。

导出一致性必须比较 ONNX 推理与实际冻结的 `VecNormalize` 实例加 float32 策略网络的输出。观测归一化先使用双精度统计量和运算，再转换为 float32。如果导出器和参考实现重复采用相同的降精度归一化，两者可能相互一致，却偏离训练出的控制器。数值检查点和准确的归一化统计量属于证据，不能替代这种独立比较。训练器及辅助源码哈希、配方、设备、环境和导出产物哈希将执行绑定到记录的来源；重写这些信息不属于兼容性修复。

### 证据与部署

动画、仿真、已录制回放和实体操作具有不同标签。辅助措施和策略交接保持可见。评估包含内置归一化器的确定性导出 ONNX，并记录准确的策略哈希、独立物理约束、任务完成情况及起始条件。奖励曲线或行走终止计数不能作为舞蹈验证结果。适用时包含站立或基线策略及空控制对照。

本地身体相位片段策略仅用于仿真。部署准备明确报告语义不兼容和缺少目标配置；它不安装或激活策略。实体发布要求受支持的运行时指令编码、官方 GPU 重训练与随机化、针对目标的验证、分别批准的安装和激活、机载看门狗及监督试验。manifest（元数据清单）声明和人工批准都不能替代失败的兼容性检查。浏览器和语言模型不拥有电机控制循环。

模型可见的摘要与证据可通过已记录的工具结果或已声明会话事件重建。高频姿态不属于对话历史。历史回放重建记录，不执行副作用。

## 考虑过的替代方案

**在 iframe 中嵌入独立 Lab。** 这会保留其全屏 UI，同时也保留独立传输、全局输入处理和任务所有权。原生 slot 组合使对话和直接控制使用同一获授权服务。

**用 TypeScript 重写 MuJoCo 和 PPO。** 这重复实现了最专业的现有代码，却没有改进用户流程。Python 提供方使科学行为保持可独立测试。

**增加第五个常驻机器人栏。** 共享可视化轨道保留对话宽度，使可视化贡献与外壳几何布局保持独立。

**将所有 61 输入、14 输出 ONNX 视为可部署。** 相同维度会掩盖不同的指令编码、关节顺序、归一化和时序。必须明确语义配置并验证目标。

**重复短记录以暗示更长的学习动作。** 重复回放不能证明持续控制能力。请求步数定义独立的仿真时限，跌倒终止仍然有效；训练回合和参考周期保持不变。

**桥接脚本变化后隐藏旧策略或重写其来源信息。** 产物完整性和当前运行时兼容性分别检查。格式 3 产物在运行时漂移阻止推理时仍可检查。不支持的格式文件保持不变，并单独列为不支持的记录，而不是解释为可执行策略或静默迁移。

**将装饰地面当作物理设置。** 表面颜色和纹理不定义碰撞几何、摩擦或可变形材料。四种视觉地面保持平面外观；实际起伏地形需要单独实现物理与评估。

## 验收标准

- 现有 GUI 在中央 Supply Chain 旁提供 Micro Duck，在右侧地球旁提供会话共享的 Robot Studio 播放器，不替换主服务器，也不丢失地球叠加层。
- 用户保存基于模型的目标和音乐配方，将其预览为非物理动作，启动和停止真实本地训练，重新加载不可变产物，评估准确导出，并播放冻结的项目绑定记录。
- 音频与姿态测试覆盖暂停、跳转、待完成恢复、提前结束、隐藏视图、会话切换和 dispose；Unicode 名称在保存与重载后保留，新草稿不能重标或改变旧记录。
- 不兼容或未验证的策略无法通过 UI 或工具调用到达硬件激活。
- 测试覆盖提供方注册与释放、进程失败与取消、片段来源信息、语义兼容性、非法传输输入及跨会话所有权。
- 真实 Loader 组合与无需密钥的组装 transcript（文本记录）覆盖工具/API 流程；浏览器覆盖检查面板切换、焦点控制、重连及明确的不可用状态。
- 构建受影响的产物并验证现有 GUI URL；仿真学习证据与连接机制测试以及任何实体试验分别报告。

## 已交付范围与延期工作

根据用户对本功能的明确要求，Robot Studio 的内置 UI 使用英文，包括导航、验证、无障碍标签、提示和安全说明。用户编写的名称和内容保留原语言；这不是对其他插件的全局语言设置变更。

原生仿真流程支持项目目标编写、本地训练、准确策略重新加载、3D 记录回放、评估和显式取消。查看器使用真实记录姿态，配合基于姿态的相机取景、定向照明和地面阴影。Studio grid、Concrete、Sand 和 Grass 都是纯视觉平面地面。Perspective、Front、Side、Top、Reset view、Expand view、画布范围内的轨道控制，以及获得焦点后的空格播放操作都只影响展示。Preview standing policy 请求对随附的 `alpha_stand` 策略执行有界仿真，而不是虚构姿态或启动训练。

高级自定义关节实验使用数值或 JSON 编写，不绑定项目或配乐；将保存目标复制到编辑器不会修改保存的预览。动作块控件明确提供添加、选择、调整长度、重排、复制和删除模板块，不提供图形关节姿态编辑。未修改的保存预览复用准确修订，冻结的播放器时间轴独立于后续编辑。

集成后的中央流程与共享音乐播放器需要各自重新构建后的浏览器证据。先前 CPU、MLX 和渲染器检查不能证明该集成或已学会舞蹈。验证必须区分源码回归、受约束的 Metal 训练/导出/重新加载冒烟测试，以及构建后的浏览器流程。[MLX 数值测试套件](../../../../packages/robot/robot-lab-microduck/tests/test_mlx_ppo.py)负责归一化和导出一致性检查；[提供方集成测试](../../../../packages/robot/robot-lab-microduck/tests/provider.e2e.ts)负责真实沙箱执行证据。CPU 冒烟测试或微型 Metal 预检通过，不代表 MLX 端到端训练、浏览器渲染、编舞学习效果或硬件安全得到证明。数值实现变更后，必须重新执行实际冻结归一化器比较和受约束冒烟测试，才能声称已验证导出一致性。

仿真和评估使用请求的控制步时限，不改变训练回合。试验独立于 Studio 记录冻结评估时限；实际记录时间戳反映已执行步数，而不是重复更短的记录。只有格式 3 运行记录可执行。早期格式文件保持不变，并显示在 Unsupported run records 下，不提供迁移或导入。完整的格式 3 产物保留可见性并明确报告运行时不兼容，推理仍重新检查不可变来源信息。回归测试覆盖时限构造、提前终止、不兼容历史与有效实验并列、产物字节保持不变，以及 UI 请求时长。

客户端同时需要 `remote` 和 `remote.robotLab` 注入。无 hook 的包装组件处理未选择会话的情况，因为 session-maybe 条目在该状态下没有 store hooks 或 actions。本地启动脚本将用户维护的附加配置保存在 `cordis.local.patch.yml`，通过 CLI 叠加选项应用，而不放入会重新生成的插件行。

[独立启动脚本](../../../../run-robot-lab.sh)组合专用的基础/Web/Robot 配置，而不导入 windows-brain 配置。下载缺少的源码需要通过克隆选项显式许可；已有检出和个人补丁保持不变。CPU Python 配置使用本地引擎的冻结锁文件，不重写源码依赖要求。可选的 `--setup-mlx` 将冻结的非 editable 依赖同步到 `DSH_HOME/robot-lab/mlx-venv` 中独立的 Python 3.12 环境，并锁定 MLX 0.31.1。`--mlx-python` 或 `DSH_MICRODUCK_MLX_PYTHON` 通过解释器绝对路径复用环境，不执行安装；后续启动必须显式选择。MLX 配置与复用互斥，选定解释器必须通过真实 Metal 执行检查，失败不回退到 CPU。显式配置方案覆盖项优先。就绪检查读取返回的布尔值；可选的 `--verify` 要求新的 CPU 提供方证据，防止跳过测试被报告为成功；它不是 MLX 训练验证。当所选端口属于同一 DSH 配置方案时，启动器会终止其完整进程树，等待退出，并在配置或构建工作之前重启它。不同配置方案或无关监听进程绝不会收到信号，并会导致启动失败。

本提案继续保留热启动派生实验、编舞专用验收、实际起伏地形物理、域随机化评估、云端训练和经过验证的实机部署。这些能力不属于已交付的仿真范围。

## 风险

本地 Python 环境和外部 MicroDuck 检出是前置条件，不是内置依赖。CPU 吞吐量和技能学习效果随机器和种子变化。官方 GPU 计算与真实机器人需要通用安装中不存在的配置。缺少的能力必须保持明显不可用，不能报告合成的成功结果。大型场景载荷与并发查看器需要有界传输；浏览器渲染不得延迟仿真或机载安全机制。
