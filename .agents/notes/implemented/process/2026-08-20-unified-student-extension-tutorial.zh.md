# Agent Note: 统一的学生扩展教程

Status: implemented

[English](2026-08-20-unified-student-extension-tutorial.md) | 中文

## 问题

用户文档讲解了各个插件、工具和能力任务，但没有提供从系统架构到完整自定义 Harness 组合的有序路径。学生必须从不同包负责的参考文档中自行推断 Profile、Cordis 插件、agent、持久会话、能力 Provider、skill、MCP 工具、命令、工作流和 Claude Code 集成如何协同工作。

在新指南中重复每个包的完整约定会产生相互竞争的参考文档，并使教程难以维护。仅发布另一个架构参考也无法为学生提供可运行的扩展示例或验证步骤。

## 决策

双语用户教程 [基于 Harness 主干进行构建](../../../../docs/user/develop/practice/backbone.md)提供有序学习路径。它从系统和模块架构开始，跟踪一个模型轮次，然后逐步构建插件、agent flow、Bundle 组合、三角色能力、skill、MCP、命令和 Claude Code 集成。

每章回答扩展点负责什么、如何使用，以及为什么它与相邻职责保持分离。示例扩展现有 `web` 或 `headless` Profile，并保留默认 agent loop，除非现有扩展点无法表达所需的轮次语义。

教程提供足够的局部行为、失败、所有权和验证细节，以完成每项练习。包 README、子系统参考、架构文档和测试策略仍是完整约定和限制的权威来源。链接将每个示例连接到这些所有者，而不复制其完整清单。

文档网站在 Develop Practice 导航中发布两个语言版本。翻译配对要求英文和中文结构及代码围栏保持一致。

## 考虑的替代方案

**仅保留独立主题指南。** 拒绝，因为学生仍需设计学习顺序，并推断独立记录的扩展机制如何在一个运行时中组合。

**将架构参考变成教程。** 拒绝，因为架构页面是面向贡献者的有序系统地图。添加设置、代码练习和用户集成过程会混合参考与教程形式，并超出其允许的详细程度。

**将完整包约定复制到教程中。** 拒绝，因为重复的配置字段、限制和生命周期语义会与其所属包文档发生偏差。

## 后果

学生拥有一条从架构到组装扩展的可发现路径，并可在每一层验证行为。教程有意覆盖较广，因此当涉及的公共集成发生变化时，维护者必须更新两个语言版本及其链接。详细查询仍分布在所属参考文档中，读者在需要完整配置或协议语义时沿链接查阅。
