# Agent Note: MicroDuck 仅用于展示的皮肤衣橱

Status: implemented

[English](2026-09-07-microduck-skin-wardrobe.md) | 中文

## 问题

不同鸭子的外观必须独立于编舞和训练。外观编辑改变录制像素，却不改变动作参考，因此无论把它当作动作编辑，还是不跟踪的视图偏好，都会导致错误的播放或检查行为。

## 决策

[皮肤衣橱](../../../../packages/client/ui-robot-lab/README.zh.md#clip-gen)将浏览与显式应用到当前换肤目标或全部鸭子分开。十种自定义外观及原厂外观使用现有网格与关节。[渲染缓存](../../../../packages/client/ui-robot-lab/src/client/clip-skin-geometry.ts)拥有重新配色的网格副本，保留拓扑和源几何；舞台沿用已有运动学和拾取机制。

已声明的会话存储在组件重新挂载间保留已应用的皮肤，但不跨浏览器刷新保存。换肤保留动作、播放状态以及待处理 AI（人工智能）导入的编辑世代，但使导出修订和人工检查失效。录制冻结外观修改。PNG 与 MP4 包含渲染后的皮肤；动作 JSON 与训练不携带外观状态。

## 考虑过的替代方案

**为服装改变模型几何或关节。** 外观定制不足以成为改变运动学、拾取或物理的理由。现有网格配色与材质即可提供外观，无需这些改变。

**将皮肤持久化到动作 JSON 或训练元数据。** 外观不是动作目标或已学会的行为。将其分离避免修改参考格式，代价是无法从动作 JSON 恢复录制时的外观。

## 后果

每只鸭子都可拥有不同外观，无需另建动作编辑器或播放时钟。已应用外观仍为临时状态；改变外观后，必须重新检查才能录制下一个 MP4。验证必须覆盖独立目标选择、动作和几何保持不变、录制锁定及重置行为；仍需检查解码后的 PNG／MP4，因为仅断言状态不能证明录制外观。
