# Agent Note: 训练前冻结的编舞评估

Status: implemented

[English](2026-09-05-microduck-frozen-choreography-assessment.md) | 中文

## 问题

保持直立的策略可能静止不动或偏离请求动作。单一汇总跟踪误差也会掩盖周期不完整、动作过弱和动作块失败。训练后再选择阈值或重建参考，会使评估随待评判结果改变。仅匹配 Python 摘要字符串不能绑定宿主解码后的科学计算输入。已测片段超过 RMSE 或运动比值限制，不一定证明计划的整个窗口必然失败：剩余测量可以改变均值或比值，但不能降低已观测到的最大位移。

## 决策

[Robot Lab 记录](../../../../docs/subsystems/robot.zh.md)在已保存试验的评估输入中支持可选且全部显式指定的版本 1 和版本 2 舞蹈标准。计划与标准版本必须匹配；不支持的版本会失败。提供方在训练前解析独立于策略的计划：准确采样参考与原始片段哈希、实际控制时钟、周期与编排动作块、关节及根刚体身份、评估器、运行时、物理设置和标准。直接舞蹈评估要求所属运行具有匹配的训练前计划；没有操作会事后生成标准或默认预设。

宿主将计划中的评估输入与已保存试验比较，并在启动训练器前提交 `RobotTrialBinding.dancePlanSha256`。此宿主规范化哈希覆盖完整解码计划，包括其不透明的 Python `sha256`。Python 摘要保留自身规范化方式；保留该字符串不能掩盖后续对解码阈值、参考身份或其他计划字段的修改。评估与反思记录仍绑定准确的已完成策略及已保存评估。

[MicroDuck 提供方](../../../../packages/robot/robot-lab-microduck/README.zh.md)以仿真器完整控制频率测量每个要求的周期和编排动作块。关节及根姿态 RMSE、参考匹配增益、幅度和水平漂移保留为不同证据；不活动参考关节的运动比值为 null。覆盖排除缺失或非有限测量，而不替换为目标值。不会通过相位对齐或时间拉伸改善记录得分。编排时长与实际运行时周期时长同时可见，因为两者不一定相同。

版本 1 保留对已观测片段 RMSE 和运动比值超限的拒绝规则，包括覆盖不完整时。版本 2 则仅在下界证明无法满足计划完整窗口限制时，拒绝部分关节或根姿态误差。未观测平方误差非负，因此已观测平方误差除以计划采样数给出最终均值的下界；各周期与动作块需要自身分母。比值依赖完整采样的均值与参考能量，所以仅在全部计划有限测量可用时才能决定结果，即使终止阻止了完成。最大漂移保持单调，在部分覆盖时仍可决定失败。记录字段保留已观测子集指标；下界不是填补的数据。未完成窗口不能通过，回合终止或提前截断仍独立导致失败。

`passed` 保留仅评判平衡的含义。独立的 `danceStatus` 与逐窗口判定按显式标准报告通过、失败或未完成。缺少舞蹈计划表示未评估，而不是成功。[UI](../../../../packages/client/ui-robot-lab/README.zh.md)展示判定、计划身份、时钟差异、测量及报告计划中的冻结阈值，包括各关节限制和运动角色。它不以当前编辑器设置替换冻结证据。可选的训练前编辑器接受明确、未经校准的标准；默认仍仅评估平衡，不提供推荐阈值。测量显示时舍入，不会重新计算或改变已保存的完整精度判定。

编辑器将未填完的数值文本保存在已有、可恢复的 `RobotDraft` 中，而非第二份已校验评估。新启用的标准从空白版本 2 限制开始；加载的标准保留版本 1 或 2。关闭时保留编辑内容，但从草稿派生请求中省略编舞。启用的无效输入阻止新试验保存／启动及未关联评估，不会静默将计划弱化为仅平衡。恢复拒绝同时包含原始编辑器与数值编舞副本的记录，保持单一活跃拥有者。已有试验保持不可变，可独立启动和评估；草稿错误不会重写或阻止其冻结评估。

## 考虑过的替代方案

**为可恢复的编舞文本使用原生数值输入框。** 浏览器清理可能隐藏已保留的字面文本，而共享数值解析器仍接受它，造成显示与状态不一致。高级编辑器使用 `type="text"` 配合 `inputMode="decimal"`，使恢复的文本及未填完的输入保持可见；有限数值与范围校验仍由共享解析器负责。

**将平衡或平均跟踪误差视为舞蹈完成。** 两者都不要求足够动作幅度或完整重复周期及动作块。独立标准保留这些区别，不改变历史平衡结果。

**选择默认值或训练后重建计划。** 预填但未经校准的默认值可能被误认为获推荐的限制；便捷的事后阈值则会削弱实验证据。准入要求全部标准，并拒绝不足的评估时限。

**复用 Python 摘要作为宿主绑定。** 宿主必须绑定其授权的解码输入，而不只是另一运行时 JSON 规则计算出的哈希。两个拥有者各自的哈希保留该责任，无需重写 Python 来源记录。

**将完整窗口规则追溯应用于版本 1。** 评估器源码哈希不能选择验证器的判定规则。显式版本 2 计划事先冻结不同语义；版本 1 报告保留其状态、原因、计划和哈希，已冻结但尚未启动的版本 1 试验仍可准入，不会自动升级。

**只显示判定，不显示其冻结标准。** 通过只在产生它的限制条件下有意义。显示这些限制及未测量维度，可避免后续草稿或舍入值看似解释了另一份评估。

**为应用随附策略命令而重建观测。** 环境的观测读取方法会推进关节速度历史；再次调用会改变控制器输入的时间语义。轨迹执行仅在返回观测的副本上覆盖运动命令，保留其他通道及原数组。会话拥有的运行推理不使用该覆盖，因此随附命令路径的观测频率缺陷不能解释自有路径的失败。[观测与标称物理语义](../../../../docs/subsystems/robot.zh.md#policy-observations)定义准确切片及固定种子的重置行为。

**把位置参考跟随失败视为目标不可行。** 位置参考基线具有关节误差伺服反馈，不具备身体平衡反馈，也不使用片段的根部俯仰目标。带扰动的站立初始姿态不是已静置稳定的平衡态。因此，位置控制器失败不能区分目标不可行与平衡控制不足，也不能据此放宽冻结阈值。

**评分抽样播放帧或填补缺失采样。** 呈现频率和看似合理的目标值不是实测物理。评分保留完整频率下的有限采样覆盖，并暴露未完成区间。

## 影响

训练预检在 RLX 工作进程 fork 前使用仅依赖标准库的辅助代码验证冻结输入；准入、评估及完成检查会重新计算参考网格。随包提供的评估辅助代码参与桥接指纹，因此测量代码变化后，在不同运行时下的重放会失效。提供方步数与记录限制仍适用；请求多周期评估可能需要提高部署限制。

两个版本都不测量节拍相位、频率误差、累计时间漂移、足部打滑或电机饱和。这些是实验性标称仿真标准，不是经过校准的通用舞蹈标准、扰动鲁棒性证据或硬件许可。行为默认练习预算同样未经能力验证，不是有学习实证支持的推荐。时序与独立对照资格验证、真实端到端评估证据、持久化入门恢复及物理世界工作仍是单独义务。不声称学会技能或完成整个学习阶段。

[学生学习闭环提案](../../proposed/feature/2026-09-05-microduck-student-learning-loop.zh.md)继续负责更广泛的入门流程及科学资格验证。本决策只取代其缺少显式训练前编舞测量的部分。[RLX 后端决策](2026-09-05-microduck-rlx-backend.zh.md)保留学习器、导出身份及数值依据；这些评估记录不依赖学习器选择。
