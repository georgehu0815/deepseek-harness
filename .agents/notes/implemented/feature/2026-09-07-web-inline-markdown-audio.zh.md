# Agent Note: 保留源链接的 Web Markdown 内联音频

Status: implemented

[English](2026-09-07-web-inline-markdown-audio.md) | 中文

## 问题

助手回复可以用 Markdown 链接指向远程 MP3 录音。在另一个标签页收听会打断阅读，而只提供内联播放器又可能在远程媒体不可用或不受支持时隐藏来源。

## 决策

共享的 [`MarkdownText` 渲染器](../../../../packages/client/ui-primitives/README.zh.md) 会在已解析的链接旁添加原生 `<audio controls preload="none">`：目标地址必须具有显式的 `http://` 或 `https://` scheme，不含内嵌用户名或密码，且 pathname 以 `.mp3` 结尾，不区分大小写。查询字符串与片段标识符不影响后缀检查。直接链接、已解析的引用式链接和自动链接使用相同规则；行内代码 URL 仍为链接，不带播放器。

原有锚点与作者提供的标签保持可见，并沿用安全的外部链接属性。播放器与锚点同级，不嵌套在锚点内；其无障碍名称取自链接的纯文本，文本为空时使用目标 URL。播放不会自动开始。浏览器原生控件不需要新增应用文案或本地化 prop。

音频加载与播放由浏览器负责。`preload="none"` 是建议性的加载提示，不承诺源站不会收到请求。原始 HTML 仍被禁用。这种展示不增加宿主代理、媒体服务、会话事件或模型 API。

## 测试

[组件测试](../../../../packages/client/ui-primitives/tests/markdown-audio.client.spec.tsx)覆盖 URL 接受与拒绝规则、标签保留、不生效的 HTML 与代码，以及跨流式输出和定稿的播放器实例同一性。[完整 Web 组合的浏览器测试](../../../../apps/web/tests/markdown-audio.e2e.ts)植入持久化 Session，并通过原生键盘操作验证播放与暂停不会触发导航。它在带 MP3 后缀的 URL 上提供确定性的 PCM 音频，将 URL 识别与编解码器支持分开；它不验证任意远程 MP3 的可用性或解码能力。

## 考虑过的替代方案

**仅保留链接，不提供播放器。** 这保留了导航能力，但读者无法留在回复中收听。

**接受原始 HTML 音频嵌入。** 启用作者提供的 HTML 会扩大不可信输出策略，超出所需的 MP3 播放范围。解析后的 Markdown 链接可以提供目标地址，无需启用任意元素或属性。

**用播放器替换链接。** 原生媒体的失败表现因浏览器与源站而异。独立保留源锚点，即使播放器无法加载或解码录音，也仍可导航到来源。

## 影响

播放器通过共享渲染器用于流式与定稿展示。MP3 后缀只标识播放候选项，不验证媒体内容；加载、解码与错误展示由浏览器负责。在浏览器策略允许的范围内，远程源站可以观察到请求与客户端网络地址。其他媒体后缀、相对目标地址、不受支持的 scheme 以及带凭据的 URL 不会创建音频元素；它们各自保持已有的链接或不可交互文本行为。

[安全助手 Markdown 策略](2026-07-23-web-assistant-markdown.zh.md)、[远程图片决策](2026-07-30-web-remote-markdown-images.zh.md)与[增量 AST 渲染器决策](../architecture/2026-08-06-web-markdown-incremental-ast-renderer.zh.md)保留其独立的安全、图片加载与流式渲染依据。音频功能补充这些决策，而非取代它们。
