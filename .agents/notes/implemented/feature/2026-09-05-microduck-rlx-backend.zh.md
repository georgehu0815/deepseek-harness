# Agent Note: MicroDuck 的显式 RLX 训练

Status: implemented

[English](2026-09-05-microduck-rlx-backend.md) | 中文

## 问题

MicroDuck 训练需要可辨识的 RLX 执行路径，且不能改变已有 DSH 自有 MLX 实验的含义。仅凭 Git 修订无法标识包含未提交修改的外部检出。导出策略也可能与降精度的检查点归一化器一致，却偏离训练时实际使用的控制器。

## 决策

[MicroDuck 提供方](../../../../packages/robot/robot-lab-microduck/README.zh.md)提供独立于 `cpu` 和 `mlx` 的 `rlx`。部署配置同时提供 `rlxPythonBin` 和 `rlxSourceRoot`；`rlxPpo` 在准入前解析数值输入。请求不能选择解释器或源码路径，学习器不可用时绝不回退到其他后端。RLX 负责 PPO、模型和观测适配器；Harness 负责会话授权、受约束的进程监管和产物准入。Metal 计算策略与价值网络，CPU 工作进程积分 MuJoCo 物理。

冻结配方绑定 RLX 源码内容指纹，包括未提交的 Python 文件与依赖声明，以及请求步数和按完整轨迹收集的步数。回合限制根据已安装仿真器的控制间隔向上取整，保留请求时长、控制间隔、完整步数和实际时长，确保片段周期不是整步数时也不会缩短动作。RLX 自身的超时修正使用终止状态价值自举，在每次重置处停止优势轨迹，并在不重复更新统计量的情况下归一化终止观测。真正终止的自举值为零。原始高斯动作保留对应的对数概率；执行器限幅不能成为限制导出策略原始均值的理由。

导出器保留 RLX 策略网络图，但在 float32 策略输入之前采用实际适配器的全精度观测统计量及 float64 运算。CPU ONNX Runtime 必须与该控制器一致，而不能只匹配检查点中降精度的归一化器。已完成的格式 3 RLX 运行通过 `artifactSha256` 中的产物 manifest（元数据清单）摘要，绑定检查点、JSON 元数据、全精度归一化器、一致性报告及 ONNX。成员缺失或变化会阻止加载。完成流程在导出及产物验证后、提交完成状态前，再次验证冻结的源码、辅助代码、模型、运行时、BAM 和片段。导出成功不能发布科学计算输入已变化的策略。数值快照是推理证据，不是可用于续训的优化器或环境状态。

可选 RLX 观测将已完成的采集／更新区间及检查点／导出工作与策略批准分开。它们保留最后一次完整完成更新中已计算的加权总目标，而不编造各损失分量。采集包含推理与环境调用；更新包含延迟执行的价值网络与优化器工作，因此两者都不是独立设备成本测量。计数与计时不含未完成或失败阶段中的部分工作：一次更新失败前已执行的优化器步数不会加入报告计数。因此零值不证明没有执行优化器工作。缺少统计表示未知，训练已用时间也不含检查点／导出。这支持检查而不改变评分语义，也不会将成功序列化变为检查点续训支持。[进度参考](../../../../docs/subsystems/robot.zh.md#run-progress)定义准确字段。

训练诊断分别保留已完成回合长度与右删失尾部：结束采集不能将未完成回合变成已观测的终止或完成。参考索引暴露量由从零开始的回合年龄与自有运行时参考推导，不是实测策略相位或跟踪。已完成运行通过已有的检查点元数据哈希绑定权威诊断，而原始进度前缀不绑定策略。公开进度投影与评估标准保持独立。

[Studio 提案](../../proposed/feature/2026-09-04-microduck-studio.zh.md)继续负责更广泛的编排、科学运行时及硬件要求。其中 DSH 自有 `mlx` 决策仍适用于该后端；本文不替换该决策。[客户端指南](../../../../packages/client/ui-robot-lab/README.zh.md)为现有控件增加各阶段的下一步说明及可选评估调整，不提供完整的入门课程。Studio 无需聊天即可显式创建或选择会话，并提供[空白会话呈现](../architecture/2026-09-05-blank-session-presentation-views.zh.md)；[Conversation 所属选择](../architecture/2026-09-05-conversation-owned-view-commands.zh.md)在 Studio Start/Open 成功后进入 Micro Duck，而创建会话不会保存目标或启动训练。

## 考虑过的替代方案

**将 `mlx` 重新解释为 RLX。** 已有 manifest 标识另一种 PPO 实现。复用该值会隐藏训练器变化，削弱可复现性。

**将 PPO 复制到 Harness，或解析示例的控制台输出。** 两者都会增加另一套算法或不稳定集成 API 的维护负担。适配器导入 RLX，通过现有监督器发布结构化进度。进度是观察值，而非完成状态的权威依据：即使保留的进度采样为 null 或落后于完成状态，终态与策略身份仍以权威记录为准。

**仅接受检查点与 ONNX 的一致性。** 两条路径使用相同的 float32 降精度统计量，可能掩盖与训练时归一化的偏差。发布要求与实际归一化器比较，并保留证据。

## 影响

用户需要在 Apple Silicon 上显式安装 Python 3.12 RLX 环境，并具备可用 Metal。提供方不安装依赖，也不修改外部检出。源码和辅助代码变化可能阻止重放；应保留完整运行产物及匹配运行时，而不是重写来源记录。两个可选 GPU 学习器都不承诺比 CPU SB3 更快或更好的学习效果。

有界桥接冒烟测试执行四步的已保存 Head Bob 运行及八步超时运行，涵盖训练、导出、策略重载、录制仿真、评估和部署阻断。其实际归一化器一致性检查报告最大绝对误差低于 `6e-7`，使用容差 `rtol=1e-4`、`atol=1e-5`。这些是集成测量，不是学会舞蹈的证据。单独的 32 步 [Loader 所属提供方测试](../../../../packages/robot/robot-lab-microduck/tests/provider.e2e.ts)验证源码模式的 RLX 执行，涵盖受约束的 CPU 物理仿真、冻结产物身份、仿真、评估和部署阻断。[真实生命周期测试](../../../../packages/robot/robot-lab-microduck/tests/lifecycle.e2e.ts)验证普通 Stop、自有工作进程失效后执行 Stop、无存活自有进程或最终策略，以及新完成运行复用容量；它不证明自动恢复或检查点续训可用。这些检查及成功构建不证明经过认证的构建后浏览器流程可用；该流程需要单独验证及人工审查。[聚焦辅助测试](../../../../packages/robot/robot-lab-microduck/tests/test_rlx_ppo.py)覆盖配置、源码身份、产物绑定和导出运算；[有界冒烟测试](../../../../packages/robot/robot-lab-microduck/tests/smoke_rlx.py)负责真实桥接验证。

[冻结编舞评估](2026-09-05-microduck-frozen-choreography-assessment.zh.md)提供不依赖学习器选择的可选实验性标准。检查点续训、实时控制器状态流、经过校准的通用编舞资格验证及实机激活仍不可用。可选训练观测不提供传输或内存测量、预热归因或冷启动与热运行成本对比。历史直立标准和训练完成标签不能认证舞蹈完成或机器人安全。
