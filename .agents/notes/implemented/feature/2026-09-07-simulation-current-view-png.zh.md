# Agent Note: 仿真当前视图 PNG 截图

Status: implemented

[English](2026-09-07-simulation-current-view-png.md) | 中文

## 问题

静态图片必须保留用户正在查看的场景，而不跳转时间轴或修改编排动作。在浏览器完成合成后读取 WebGL 画布，可能得到已清空的绘图缓冲区，而非可见场景。

## 决策

仿真工作区的**截取视图（PNG）**按现有画布实际像素缓冲区的分辨率下载图片。[姿势舞台](../../../../packages/client/ui-robot-lab/src/client/ClipPoseStage.tsx)在同一个同步任务内，先按当前场景与相机立即渲染，再读回 PNG。图片包含可见几何体、环境及场景标签，不含 HTML 控件。此操作要求预览就绪；MP4 导出期间禁止静态截图。

截图仅作用于呈现：不为姿势添加关键帧、不跳转时间轴、不修改片段，也不改变检查状态。文件通过浏览器下载，不作为已保存的项目资源，也不作为封面元数据嵌入 MP4 或片段 JSON。[Clip Gen 决策](2026-09-05-microduck-native-clip-gen.zh.md)继续负责动作编写与经过检查的 MP4 录制。

## 考虑过的替代方案

**启用 `preserveDrawingBuffer`。** 为偶发截图保留每一帧，会改变渲染器的缓冲区行为。立即渲染并读回可获取所需图片，无需承担这项持续成本。

**不渲染，直接读取画布。** 按需渲染的预览可能在合成清空缓冲区后一直空闲。PNG 编码成功本身不能证明文件包含显示的场景。

## 影响

静态截图保留用户视图，并允许截取未设为关键帧的姿势，不削弱 MP4 检查要求。分辨率由现有画布和像素比上限决定，不提供独立导出尺寸。结果只是视觉参考，不是物理或策略证据。

## 验证

[浏览器 PNG 回归测试](../../../../apps/web/tests/clip-image-capture.e2e.ts)在设备像素比为 2 的 Chromium 中运行仿真组件，在空闲帧后下载并解码 PNG，检查像素缓冲区尺寸、不透明且非空白的像素，以及相机／环境编辑后的背景变化。它使用测试组合，而非现有运行中的 GUI。[仿真组件测试](../../../../packages/client/ui-robot-lab/tests/clip-simulation.client.spec.tsx)负责预览不可用及 MP4 导出时的禁用保护；mock 编码器不能证明 WebGL 读回内容。
