# @deepseek-ai/dsh-client-ui-robot-lab

English | [中文](README.zh.md)

## Summary

Native **Micro Duck** contributes a center `conversation.view` tab (`micro-duck`, order 40, beside Supply Chain) with accessible, localized **Train** and **Evaluate** subtabs. Train is selected initially; only the active panel is visible and uses the full center width. There are no step numbers or Next footer. The sidebar's **Robot Studio** action opens the `robot-lab` tab in the [layout visual workspace](../ui-layout/README.md). Its session-maybe wrapper renders the session-scoped `robot-lab.visual.player` child. This is native slot composition, not an iframe or standalone Lab application.

The center entry declares two single/session child slots: `conversation.micro-duck.learning-plan` and `conversation.micro-duck.learning-review`. They receive no owner arguments; each registration binds the shared session draft store and the same captured-session LabClient and playback owner as the center and player. Train contains the learning brief, assessment planning, trials and training controls; Evaluate contains policy evaluation, evidence, reflection, episode replay and hardware-blocker inspection. Both panels and child slots remain mounted when hidden, preserving unsaved inputs, expanded details and independent scroll positions across subtab switches. The session view store selects Evaluate for `evaluate` or `perform` and Train for other retained page values. Mounting or switching subtabs starts no Robot Lab operation. The [center-layout decision](../../../.agents/notes/implemented/simplification/2026-09-05-microduck-train-evaluate-columns.md) records the scope.

The browser plugin requires `slots`, `layout`, `remote`, `remote.robotLab`, `locale`, `sessions` and `uiConversation`. It calls the authenticated `robotLab.request` [Robot Lab service](../../robot/robot-lab/README.md); without the namespace injection it waits rather than accessing a partially published Remote. It uses no browser-held credentials or direct Lab URL. Direct non-AI controls and local music need no model key; chat and SequenceByAI use the configured provider, including an existing AgencyCopilot sign-in.

## Configuration

The browser plugin validates these fields at activation. Backend limits also apply; viewer and music settings never alter physics or hardware admission.

| Field | Default | Meaning |
|---|---|---|
| `pollIntervalMs` | `2000` | Active-run refresh interval; integer at least 250 milliseconds |
| `maxDpr` | `1.5` | Canvas pixel-ratio ceiling, from 1 through 3 |
| `simulationSteps` | `1000` | Initial simulation and assessment horizon, integer 1–3000; each trial freezes its independent assessment recipe |
| `defaultEnvCount` | `4` | Positive initial parallel-environment count, editable in training |
| `evaluationEpisodes` | `5` | Positive evaluation episode count |
| `evaluationSeed` | `0` | Nonnegative integer evaluation seed |
| `maxTerminations` | `0` | Nonnegative allowed termination count |
| `minMeanUprightFraction` | `0.9` | Required mean upright fraction, from 0 through 1 |
| `quickCheckSteps` | `1024` | Positive setup-check training budget; not a skill-learning target |
| `musicSampleRate` | `22050` | Generated mono PCM sample rate; 22050 or 44100 Hz |
| `maxMusicSeconds` | `120` | Positive finite synthesis duration ceiling |
| `maxMusicSamples` | `2646000` | Positive integer allocation ceiling fitting mono PCM16 RIFF; both duration and sample limits apply |
| `playbackHudIntervalMs` | `50` | Positive browser-timer interval for playback indicator notifications; renderer time is read separately |
| `maxGroupMembers` | `8` | Positive integer ceiling for each Clip Gen view, including Duck 1, and each policy duck roster; roster add, duplicate and file import respect it |

## Clip Gen and Simulation workspace

The **Clip & Motion Gen** center tab opens the **Clip Gen** panel, with **Simulation workspace** in the existing right visual column. Both use one declared session-scoped authoring store; they do not replace Micro Duck's Train/Evaluate subtabs or Robot Studio's policy player. **Design sequence** expands supported English or Chinese activity requests into deterministic ordered recipes. **SequenceByAI**, in the Dance guide toolbar below **What should the duck do?**, queues the exact activity or lyrics to the current session's agent. The request instructs that agent to load the [microduck-choreography skill](../../bundle/robot-lab/skills/microduck-choreography/SKILL.md), plan contiguous timed segments, then author matching fourteen-joint motion using the installed mapping and limits. It uses the session's configured model, not another provider connection or agent. Both paths produce editable references, not trained skills.

**Activity plan → Dance guide library** offers three locale-owned built-in prompts and browser-local custom guides. Text-only guides replace the activity prompt without generating motion. Guides containing a saved sequence load its exact validated keys and BPM into **Animate & verify**, replace the prompt and clear manual verification; they do not rerun AI or the recipe planner. **Add guide** opens a name/description editor with the current prompt prefilled. **Save guide** requires a trimmed nonblank name up to 80 characters and a nonblank description up to 2,000 characters; duplicate custom names are rejected case-insensitively. Descriptions remain verbatim across locale changes. Successful AI generation adds the formatted generated guide and exact model-bound sequence under a unique clip-derived guide name; the original activity or lyrics remain in the logged user request. Custom edit/delete controls are not provided.

SequenceByAI accepts only its request's committed final JSON after a successfully completed turn. The V2 request requires a timed guide alongside the existing version-1 model-bound sequence; historical V1 event projection does not permit guide-free replies for new requests. Guide segments must have finite times and positive duration, cover zero through the clip duration without gaps or overlap, and contain nonblank descriptions. The prompt requests descriptions in the activity's language; validation does not detect language. The complete guide, formatted as `start–end s: description` lines, must fit 2,000 UTF-16 code units; `draftMaxBytes` separately bounds the complete UTF-8 reply. [Request and reply validation](src/client/clip-sequence-agent.ts) owns the exact JSON fields.

Invalid, interrupted, wrong-model or out-of-range output leaves the draft unchanged. A valid result replaces the activity input with the formatted guide and loads exact keys/BPM into **Animate & verify** only if the captured edit epoch is unchanged. Otherwise the result remains a candidate with guide preview and explicit **Replace activity plan and timeline**. **AI timed activity guide** shows the last received guide, not a description regenerated from later draft edits. **Download AI motion JSON** explicitly downloads that result's bare clip object in the **Load clip JSON** format, not the response envelope or model-bound wrapper, as `microduck-motion-${bpm}bpm.json`. Receipt never starts download, playback, verification, training or export; no agent filesystem write is involved.

Cancellation, leaving Clip Gen or plugin disposal discards the pending local import, not the shared agent turn. Local waiting has no hard timeout. The request permits only the choreography skill load and prohibits other tools, subagents, training, simulation, evaluation and hardware calls. These are prompt instructions, not an executor-enforced tool sandbox; the current session retains its configured authority. The [SequenceByAI decision](../../../.agents/notes/implemented/feature/2026-09-05-microduck-session-sequence-ai.md) records correlation and ownership.

The root-scoped `conversation.clip-gen.guides` child slot owns an independently declared protected store. Custom `guides` and `nextId` persist, including optional model-bound sequences; existing version-1 text-only guides remain readable. Built-ins come from locale copy. The library is shared across sessions and reloads on the same origin, browser and profile—not through server or account synchronization. `draftMaxBytes`, passed as `maxFileBytes`, bounds the complete library envelope and AI reply. Wait for saved status before relying on persistence: pending or blocked additions remain usable in memory but may be lost. Corrupt records, quota failures and conflicts preserve stored bytes without silent overwrite. Unsaved editor inputs, subsequent timeline edits, media and evidence are excluded; [protected recovery](../store/README.md#browser-recovery) owns locking and revision checks.

**Animate & verify → Load a generated dance** offers six original MicroDuck JSON sequences and six larger **v2** choices: Bachata, standing breakdance, Cumbia, gentle martial arts, robot pop and Salsa. Each option shows its duration and BPM. Selecting one validates its exact model fingerprint, joint order, current motion limits and exported-clip byte budget, then copies its keys, tempo and authored timed guide into the session draft. Save edits before selecting: success replaces the timeline, stops playback, resets the playhead and clears manual review; incompatibility leaves the draft unchanged. The picker returns to its placeholder so the same dance can be reloaded after editing. Originals remain unchanged, and loading neither adds a browser-library guide nor starts AI, training or export. The [bundled presets](src/client/dance-presets.ts) are authored interpretations, not direct G1 joint mappings or proof of physical feasibility.

The larger v2 dances run approximately 56–61 seconds, with 16–21 mm foot lifts, 22 mm forward/back swing reaches and bounded body turns up to about ±52°. They preserve feasible foot spacing instead of forcing wider lateral splits. **v2 names the dance revision; these files use preview schema 3**, retaining solved root coordinates and rigid support-foot intervals. Validation includes the installed native kinematics; raw pose/key editing and training stay locked to preserve contacts. Renaming, retiming, playback and JSON export remain available. Independent native forward-kinematic checks at keys, contact boundaries and 50 Hz found support-foot drift below 0.35 mm; this is sampled geometry evidence, not dynamic balance or hardware clearance.

Each of the twelve dances defaults to its embedded, original genre-style Ogg rhythm. The **Original dance rhythm** region also offers three credited SoundHelix excerpts: **The Stationary Ark — Low pH Arktic Clubmix**, **Spy vs. Spy — Chill-out Acid Squeeze Mix**, and **SoundHelix Song 1**, all by **T. Schürger / SoundHelix**. These are curated choices, not chart rankings. Native players audition one option at a time without selecting it; radio buttons select the recording for **Play sequence** and the next MP4. A soundtrack change pauses motion and invalidates review without changing keys. Custom clips without an original rhythm can still select any alternative. Loading another timeline resets the choice to original; renaming and pose edits retain it.

The alternatives are bundled 32-beat excerpts normalized to 120 BPM, with estimated source beat grids and short fades at their joins. Preview and export share one source-rate plan: alternatives change speed and pitch to the authored BPM and repeat to fill the clip, rather than compressing a whole song into its duration. Duration edits scale BPM with key times; each full dance loop returns music to its initial phase. This is timing alignment, not verified movement-to-music synchronization. The [soundtrack decision](../../../.agents/notes/implemented/feature/2026-09-07-clip-gen-selectable-music.md) records the tradeoffs; [NOTICE](NOTICE) preserves source permissions.

**Play sequence** starts the selected recording and motion together; audio time drives the playhead. Pause, seek, loop and preview speed remain coupled. **Mute dance audio** and volume affect audition and motion preview without changing the clip or review. Selection never autoplays. Hidden tabs, unmounts, replacement and MP4 capture silence playback; media failures pause with an explicit error, and retrying Play clears that error. Audio choices are session-local, are not inferred from editable names and are excluded from clip JSON and saved guide sequences.

The mapping shows fourteen servo targets in the installed model's order; free-root pitch is separate. Animate provides linear keyframe interpolation, timeline seeking, joint sliders and coupled rig controls constrained by model limits. In the preview, drag empty background to rotate the view, scroll to zoom, or drag a robot part around its hinge to edit its joint. The right preview uses actual model meshes and forward kinematics from optional `RobotScene.kinematics` metadata; missing metadata disables live posing and MP4 generation rather than substituting a decorative robot. This is authored motion, not a dynamics simulation, trained policy or hardware command. The [Robot reference](../../../docs/subsystems/robot.md) owns scene metadata.

The right column provides camera presets, Orbit/Pan/Pose modes and zoom; **Environment** controls floor appearance/visibility, measurement grid, world axes, background, lighting and robot wireframe. These are visual settings, not gravity, friction or terrain physics. **MicroDuck controls** exposes the same fourteen joints, nine rigs, root pitch, heading and reset controls as the center, including finite, in-range exact numeric inputs. Key or explicitly discard pose changes before seeking. A neutral clip can be created directly when the installed model is available. Keyframe navigation, looping, 0.25×–2× preview speed and **Review & export** remain in the right column. View preferences survive remounts in the same session visit but not refresh or clip JSON export; MP4 always records at authored speed. MP4 capture locks view and pose mutations, and version-3 planted-foot clips retain their pose-edit lock.

**Simulation workspace → Ducks in this view → Add duck** adds a companion that defaults to **Follow Duck 1**, including later primary-dance loads and unkeyed pose edits. Each companion can choose any compatible bundled dance independently or return to following. Only Duck 1 has joint/keyframe editing. Independent selections retain their validated preset when the primary timeline changes; incompatible installed model metadata makes the preview unavailable until that selection is removed or returned to following. Add, remove and dance selection pause playback and clear manual review. Adding or removing a duck refits the group at normal zoom; numbered labels retain their identity after removal.

All ducks use one canvas, camera, floor, playhead and selected soundtrack. Independent dances follow Duck 1's beat position and current BPM: shorter looping dances repeat, non-looping dances hold their final pose, and longer dances end with Duck 1's video. Model-sized grid offsets separate the figures visually while preserving native root translation, roll and heading. These are authored kinematic references, not interacting MuJoCo physics bodies, collision avoidance or independent learned controllers.

Both **Generate MP4** buttons record the entire displayed canvas, including all configured ducks and their labels, for Duck 1's duration. Capture locks additions, removals and dance choices. Completed multi-duck output states its captured count and labels the accompanying download **Save Duck 1 clip JSON**: that JSON describes only the primary motion, not the whole group. Extra duck choices and layout are transient session state, excluded from motion files, saved guides and training. The [Clip Gen decision](../../../.agents/notes/implemented/feature/2026-09-05-microduck-native-clip-gen.md) records shared geometry, clock and export ownership.

**Capture view (PNG)** beside **Focus duck** downloads the current Simulation scene in one click at the canvas's backing resolution, including the current camera, pose, environment, visible ducks and their scene labels, but excluding HTML controls. It requires a ready preview and is disabled during MP4 export. Capture does not seek, key a pose, change the clip or alter manual review; an unkeyed pose can be captured as displayed. The PNG is a browser download, not embedded cover metadata in MP4 or clip JSON. The [PNG capture decision](../../../.agents/notes/implemented/feature/2026-09-07-simulation-current-view-png.md) records the render-before-readback requirement.

**Animate & verify → Skin wardrobe** offers ten custom finishes (`velocity`, `varsity`, `weekend`, `sakura`, `candy`, `punk`, `cyber`, `explorer`, `nautical`, `disco`) and **Original factory finish**. Browsing a card or selecting Original only chooses a candidate; use **Apply to Duck…** or **Apply to all… ducks** to change the canvas. **Current duck · appearance** selects the appearance target independently of dance selection and Duck 1's joint editor. Cards show model-derived color sketches when available, otherwise palette swatches; inspect the full applied finish in Simulation.

Applied skins and the appearance target survive component remounts within the same session visit, not browser reload. New companions inherit Duck 1's skin; removing the targeted companion clears its skin entry and returns the target to Duck 1. Applying a different skin invalidates the export revision and manual review but preserves playback, playhead and timeline. Capture locks skin changes. PNG and newly recorded MP4 use the current canvas skins; motion JSON and training exclude them. Finishes change colors and materials, not model geometry, joints or motion physics. The [skin decision](../../../.agents/notes/implemented/feature/2026-09-07-microduck-skin-wardrobe.md) records this separation.

**Animate & verify → Joints / Rig** uses compact duck-part icons in its mode controls, body-group headings, fourteen joint controls, nine coupled rig controls and separate root-pitch control. Each joint combines a localized readable label with its raw model name, one-based servo number, movement help, radians/degrees, installed range and default. Displayed limits and defaults are rounded to three decimals; sliders and resets use the actual values. Rig help describes the coupled movement and identifies the joints limiting travel below its range. Its **Amount** is a coupled adjustment, not an individual physical joint angle. Left and right mean the robot's own sides. Positive and negative angles follow model-local axes, not screen directions; inspect a small change in the live preview before increasing it.

The icons highlight relevant model parts against a muted whole-duck silhouette. They are static SVG projections of the loaded model's meshes at its neutral STAND pose, not photographs, live pose thumbnails or dynamics results. Missing scene/kinematics or incompatible joint order produces an explicit generic mechanical fallback rather than guessed anatomy. Icon rendering adds no WebGL contexts, model prompts or tool calls. The [authoring controls](src/client/ClipAnimate.tsx) own the labels and mappings; [the Clip Gen decision](../../../.agents/notes/implemented/feature/2026-09-05-microduck-native-clip-gen.md) records artwork ownership.

**360° left + right · 20 s preview** loads an 81-key, 120-BPM example: knee pulses at 0–2 seconds, a full left turn with alternating leg gestures at 2–10, a full right turn at 10–18, then pulses and neutral standing at 18–20. It replaces the current timeline without starting playback, training or export. **Heading · preview only** edits the whole robot's angle about world +Z (positive left, negative right), independently of hip yaw and camera orbit. Angles interpolate without wrapping, so `0 → 2π → 0` preserves both full turns. The model rotates about its root; planted-foot contact, displacement and balance are not simulated.

Manual **Load clip JSON** accepts unchanged version-1 training references and browser-only versions 2 and 3. Version 2 requires `rootYaw` in every key, bounded to ±2π radians, alongside `t`, fourteen `joints` and `rootPitch`; its last key must equal `duration`. Editing heading promotes all version-1 keys with zero heading before changing the pose; reset does not downgrade the clip. Saved JSON and matching MP4 JSON preserve the version and unwrapped headings. **Use for training** is disabled for version 2, and both custom training import and backend admission reject it; a version-1 key containing `rootYaw`, `rootPosition` or `rootRoll` is also rejected rather than silently stripped. SequenceByAI and its saved model-bound guide sequences retain their version-1 training-reference format. The [preview validator and turning recipe](src/client/clip-preview.ts) own the browser-only format.

**Walk left 360° + right 360° · 20 s** creates a different, version-3 stepping preview at 120 BPM. It holds neutral double support at 0–2 seconds, takes 32 alternating half-beat steps left at 2–10, reverses the stepping order for 32 steps right at 10–18, and holds exact neutral at 18–20. Each swing foot lifts about 5 mm. Coupled inverse kinematics solves the ten leg joints plus body translation and roll while preserving rigid stance-foot targets. This turns around the standing center rather than walking a large circular route. Missing kinematics, resource excess or unreachable contacts reject generation without substituting a sliding spin.

This example's version-3 JSON binds `modelSha256`, 259 solved keys and 68 support intervals. Keys add native-world `rootPosition` in meters and `rootRoll` in radians; `rootPitch` stays zero. Each contact records `start`, `end`, `foot`, a fixed ankle-body `position`, and an `[x,y,z,w]` unit `quaternion`. Import checks joint/root bounds, exact neutral endpoints, complete support coverage, no overlapping intervals for the same foot, and sampled stance drift at key boundaries and eight subdivisions per interval. Admission limits are 0.5 mm translation and 0.01 rad orientation error, not physical safety thresholds or a continuous-time proof. Rendering uses a fixed standing-ground offset rather than moving the floor alignment per pose. To preserve contacts, raw joint, heading, reset and key edits are locked; naming, retiming, playback and export remain available. Retiming scales support intervals with keys. Version 3 is preview-only and cannot enter training. [Walking authoring and validation](src/client/clip-walking.ts) and the [coupled solver](src/client/clip-leg-ik.ts) own the implementation; no physics integration, balance assessment or training runs occur.

Pose edits remain **unkeyed** until **Key this pose** commits them. Playback, JSON saving and video generation cannot consume an unkeyed pose. **I reviewed this revision in the preview** is a manual acknowledgement, not an evaluation result; edits invalidate it. **Generate MP4** requires the current keyed, reviewed revision and records one complete sequence from zero, regardless of preview looping. Keep the browser tab and Simulation workspace visible throughout recording. Cancellation or unmount releases the recorder's tracks, listeners and timers; incomplete generations cannot publish a finished video.

**With audio** is checked by default beside generation controls and **Generated clip → Save MP4 file**. Both locations share the preference. A dance with a soundtrack prepares audio and silent MP4 variants in the same recording; the checkbox selects the downloaded file and completed-video player without recapturing. Unchecked downloads use a `-silent.mp4` suffix. Clips without a soundtrack produce video only and show a disabled checkbox with that explanation. Preview mute, volume and playback speed do not affect export: audio plays at its source level using the authored timing plan, including pitch changes. No microphone is used. A completed video's soundtrack and credit stay tied to that capture, not later draft selections; changing music marks it stale and requires generation again. For SoundHelix music, **Save music credits** downloads a companion attribution JSON. Credit T. Schürger / SoundHelix when sharing the MP4; the credit is not burned into video frames.

Recording requires browser `MediaRecorder` support for `video/mp4`; soundtrack variants additionally require Web Audio decoding and an MP4 audio encoder. Audio preparation or recording failure publishes no completed substitute. An unsupported browser receives an explicit error. The utility checks the recorder's MIME and the MP4 container and rejects empty media payloads. It never renames WebM or sends video to a transcoding service. Completed output provides browser playback, **Save MP4 file**, and **Save matching clip JSON** for the exact recorded reference. Browser download permissions determine where files are saved; an automatic download may require the explicit save link. Download both files before refreshing: Clip Gen drafts and media are transient, not protected authoring recovery or server artifacts. For later custom training, use version-1 keyframe JSON through the existing RL Training workflow, not preview-only versions 2/3 or the MP4; exporting or opening training does not admit a run. The [Clip Gen decision](../../../.agents/notes/implemented/feature/2026-09-05-microduck-native-clip-gen.md) records these ownership and evidence limits.

## Projects and training

Robot Studio motion-editor labels use English product copy; Clip Gen, learning-plan and review controls, recovery controls and recorded assessment verdicts follow the configured locale. Names and authored content retain their original language. With no active session, Robot Studio offers **Start a Studio session**, an optional workspace choice, and an **Existing session** selector through the Session Controller. Leaving the workspace unset uses the application's default directory without grouping the session. Merely viewing this entry does not send chat, make a Robot Lab request or start training; explicit creation needs no model key. A successful Studio Start or Open selects **Micro Duck** through the Conversation-owned navigation command, including when its body has not mounted yet. Its [blank-session presentation opt-in](../../../.agents/notes/implemented/architecture/2026-09-05-blank-session-presentation-views.md) exposes the tab without requiring a chat turn or fabricating activity.

Session and workspace lists must be ready before creating or selecting a session. Pending creation blocks duplicate starts. **Do not open when ready**, choosing another session, or unmounting the entry cancels automatic navigation, not an already admitted creation: the session may still appear in the existing-session list. Creation or opening errors remain visible; inspect that list before retrying. Session creation is not project saving or training admission.

Train's initially collapsed **Training target** section lists nine original experimental dance/action templates derived from the installed MJCF model's actual joint order, default pose and limits. The same section edits master move size, tempo, beat count and a seeded soundtrack recipe. **Motion blocks** composes ordered templates with per-block length and relative move size; add, reorder, duplicate and remove actions update the first-template identity and motion/music beat totals atomically in the draft store. Effective block size is relative size multiplied by master size. **Save revision** creates an immutable session-owned project. **Preview target in Studio** reuses an unchanged saved revision; an edited draft is saved before its exact revision's MuJoCo forward-kinematic frames are requested. **Refresh library** remains available after connection. **Target preview · Not physics-tested** means desired motion, not balanced dynamics or a learned policy. Model joint-limit checks do not establish physical feasibility.

Project format 2 freezes the recipe, model/profile, every resolved block/template, whole-composition training recommendation, compiled joint targets and SHA-256. The UI merges the project's resolved reward overrides over its recommended behavior's registered defaults, rather than using the first template's settings for the whole routine. Templates, clips and music retain format 1; runs retain format 3. Older project formats are rejected without migration. Project-bound training freezes the selected revision and soundtrack in its run. Editing or loading another draft cannot rename, retime or attach a different soundtrack to an existing recording. Unsaved drafts are view state, not durable projects. **Save revision** commits the target, while **Save trial** commits the reviewed brief and settings without starting training. Browser authoring recovery is separate from either immutable record and never turns an unsaved draft into evidence. The [user guide](../../../docs/user/guide/robot-lab.md) covers the direct-control workflow; [Robot types](../../../docs/subsystems/robot.md) define the records.

**SB3 PPO — CPU (CPU physics)** selects `cpu`; **DSH MLX PPO — Apple GPU (CPU physics)** selects the DSH-owned `mlx` learner; **RLX PPO — Apple GPU (CPU physics)** selects `rlx` from the configured RLX checkout. Both optional learners use Metal for policy and critic learning and CPU for MuJoCo/BAM physics. The optional recipes have no symmetry loss and are not numerically equivalent to the CPU trainer; no speedup or equal learning quality is promised. An unavailable selection fails without switching learners. Overall runtime readiness or CPU readiness does not imply `backends.rlx.available`; inspect the selected learner's own reason. RLX requires both `rlxPythonBin` and `rlxSourceRoot` in the deployment serving this Web page, or both `DSH_MICRODUCK_RLX_PYTHON` and `DSH_MICRODUCK_RLX_SOURCE_ROOT` when that deployment uses the [Robot Lab bundle](../../bundle/robot-lab/README.md). Configuring another profile or checkout does not enable this running GUI. A quick check establishes setup behavior, not a learned dance. **Evaluate** assesses exact exported hashes against saved criteria and reports hardware blockers without a hardware activation callback. The center has no exploratory Perform controls; Robot Studio retains its group recording and standing-policy preview controls.

**Train → Advanced: custom joint experiment** accepts a numeric/JSON joint clip and a registered reward recipe. Copying a saved target into this editor does not edit the project or its target preview. Custom training freezes its clip without `projectRevisionId`, so its recording has no project soundtrack. The custom experiment ID is distinct from a Unicode project display name. A numeric clip is not a balance or safety test.

Only run format 3 is executable. Older files stay untouched under **Unsupported run records**. Intact format-3 policies incompatible with the current runtime remain inspectable with their exact reason, but cannot simulate or evaluate. There is no migration, arbitrary ONNX import or warm-start action. An earlier evaluation does not establish current compatibility.

## Authoring draft recovery

The configured plugin restores this browser's authoring draft for the exact Session. Its factory remains in-memory unless a caller explicitly supplies persistence options. Recovery includes only the target recipe, learning brief, assessment and training inputs, plus a parent-reflection id hint. Optional choreography editing shares this `RobotDraft` owner: enabled state, raw numeric text and selected movement joints survive navigation and protected recovery, including incomplete inputs and disabled work. It excludes reflection notes, rosters, policy/report selection, caches, evidence and frames. The restored target is dirty with no saved revision; no save, training, evaluation or playback starts. A parent hint must appear in current loaded Session history before an improvement trial can be prepared; **Refresh library** reloads that history, and the Host still validates the committed parent. Missing installed target references require explicit review rather than substitution.

**Authoring draft recovery** reports empty, restored, pending, saved or blocked state. Wait for saved status before relying on browser recovery; pending or blocked edits may be lost on close. Valid records can restore without Web Locks, but automatic writes cannot proceed without locking. Invalid or unsupported records, size/storage failures and conflicts preserve existing saved bytes and local unsaved edits. On conflict, use **Export authoring draft** before reloading to inspect the saved winner, then explicitly import if you want to replace the editor. **Import authoring draft — replaces current editor** accepts only a bounded versioned file addressed to that same Session; it does not force a blocked writer to overwrite storage. Both file actions enforce the configured complete-file limit. Protected authoring records and portable draft files retain envelope version 1 while accepting nested choreography criteria version 1 or 2; an unsupported nested version is rejected, not upgraded.

Recovery accepts older payloads without a raw choreography editor but rejects a payload containing both that editor and numeric `assessment.dance`. Import replaces the editor, including clearing stale raw inputs absent from an older file. Preparing another duck's training plan resets the criteria draft; opening an improvement draft instead restores its parent's recorded criteria without carrying unrelated raw edits.

These are unencrypted browser-local records, not project revisions, trials, evidence or cloud backup. Protected records survive scope and HMR teardown and are not automatically pruned; browser site-data removal can erase them. Save reflection notes explicitly before reloading because they are excluded from recovery. [Protected recovery](../store/README.md#browser-recovery) owns the lock, revision and teardown rules. Saving a project or trial remains an explicit independent operation.

## Learning trials and reflection

**Your next step** explains training, evaluation and their evidence limits. **Training target** suggests Head Bob when available, without claiming a trained skill. Train distinguishes a setup check from a learning budget and explains missing projects, incomplete briefs, invalid settings, busy operations and unavailable learners. The locale-owned **Practice — behavior default (unqualified)** option uses the behavior's default budget, not a budget demonstrated to teach the routine; longer practice does not establish skill quality. The assessment summary stays visible; **Advanced: edit assessment criteria** exposes optional tuning before a trial freezes its criteria. **Training progress · not assessment results** keeps collection progress separate from measured policy evidence. These prompts guide existing controls; they do not supply a complete beginner curriculum or certify the routine.

**Advanced experimental choreography criteria** is an explicit opt-in for project-bound trial planning; balance-only assessment remains the default. New criteria use version 2 with eight blank scalar inputs, fourteen blank per-joint RMSE limits and no selected movement joints. Labels come from the selected profile's fourteen named joints; an unavailable profile produces a notice, not an invented mapping. Every numeric value and at least one movement joint must be supplied within the displayed ranges. Loaded version-1 or version-2 criteria retain their version. Disabling keeps the inputs but omits choreography from draft-derived requests; enabled invalid input blocks **Save trial**, **Save and start trial** and unlinked **Check this policy**, never falling back to balance-only. Saved trial criteria remain read-only JSON, and **Start saved trial** and **Evaluate trial** use their frozen recipe independently of draft validation. Valid editor values do not replace the provider's target, horizon and plan checks.

**RLX training observations** shows recorded rollout/update pairs, actual optimizer steps within fully completed updates, the last fully completed update's mean weighted total objective and completed interval timings. Partial work in unfinished or failed phases is excluded; an update may apply minibatches then fail without increasing the reported count. Zero counts or times do not mean no work occurred. They are training observations, not separate policy/value/entropy losses or assessment evidence. Missing statistics and null timings are unknown, not zero; observations may lag. Collection includes environment calls and inference, while update includes GAE, deferred critic and optimizer work; neither is isolated CPU/GPU time, and transfer time is not measured. Checkpoint and ONNX/parity export durations appear only after those operations succeed and are excluded from training elapsed time. No checkpoint-resume or skill claim follows from these displays.

The **Learning brief** records a goal, prediction, planned change and evidence to examine. These are the student's pre-training plan, not measured results. Empty fields show detailed examples to customize; placeholders are not saved and the brief does not change motion, training or assessment settings. **Save trial** freezes that brief, a saved project revision, training inputs and seeded assessment criteria without starting training. **Save and start trial** commits the trial first, then starts its one admitted run; a failed start preserves the saved trial for explicit retry. **Start saved trial** uses the displayed immutable settings, not the current draft. Advanced custom experiments remain unlinked and are not retrospectively presented as pre-registered trials. Their **Exploratory assessment settings** edit the assessment draft in Evaluate; **Check this policy** uses that draft without modifying any frozen trial.

**Evaluate trial** uses the frozen episode count, requested horizon, seeds and upright/termination thresholds. History and readiness settle independently in one refresh. Failed reads retain prior data and report operation-labelled errors without hiding readiness or unrelated successful results; disabled readiness does not prevent history loading. Report selection identifies exact policy bytes, trial/run and target revision. Comparison requires both runs' recorded provenance and equal assessment criteria, physics, observation semantics, source fingerprints, bridge hashes and evaluation-runtime versions before presenting like-for-like deltas. Trainer backend, device, dependencies and actuator differences are described separately. Tracking means include only measured episodes and display coverage counts; differing targets or measured episode cohorts prohibit tracking-error deltas. Reward totals are not compared. Upright criteria do not establish choreography completion, robustness or hardware suitability.

**Choreography assessment** displays a report's separate choreography verdict, frozen plan hash (`dancePlan.sha256`), authored versus simulator cycle clocks and their difference, and per-cycle/per-block measurements. Joint/root RMSE, amplitude, reference-matched gain, drift and finite-sample coverage retain their recorded values; missing evidence is not zero or success. The elapsed reference-cycle count describes executed control steps, not successfully assessed choreography cycles. Missing or different plan hashes prevent like-for-like choreography comparison. Balance `passed` is unchanged and independent.

**Criteria frozen before training — not the current editor settings** reads thresholds directly from the selected report's plan. It shows required cycles and episode pass fraction, per-joint RMSE limits and movement roles, root-orientation and horizontal-displacement limits, amplitude range, minimum zero-lag reference gain and reference excursion. Movement requirements apply to selected joints and reference-active blocks; stationary blocks retain positional checks. Measurements are rounded for display; the stored verdict uses full recorded precision, not rounded values or current editor settings.

The disclosure distinguishes version-1 observed-fragment rejection from version-2 whole-window bounds. For version 2 it labels the derived largest-joint and root RMSE lower bounds separately from observed-sample metrics, using each cycle or block's own planned length. These are derived bounds, not extra measurements or recomputed verdicts; a bound within its limit cannot establish a pass. Version-2 movement ratios remain observed-subset values and are decisive only with full planned finite coverage. Historical version-1 verdicts remain unchanged.

Neither version measures beat phase, frequency error, accumulated timing drift, foot slip or motor saturation. Nominal simulations do not assess robustness to disturbances. The optional editor supplies no calibrated preset or recommended thresholds, and evidence displays continue to read the frozen plan rather than the draft. [Frozen choreography assessment](../../../.agents/notes/implemented/feature/2026-09-05-microduck-frozen-choreography-assessment.md) records the limits; neither verdict is general skill or hardware qualification.

**Re-simulate episode** requests new frames using the report's saved inputs and requires an owned completed run. The selected current policy must match both the report's policy ID and SHA-256; identical bytes under another policy ID do not grant replay eligibility. Shipped policies without an owned run are ineligible for episode re-simulation; Robot Studio retains explicit group recording and standing-policy preview. The player labels episode re-simulation as new frames, never the original evaluation recording. Original metrics and verdict remain unchanged; missing or incompatible source artifacts prevent replay instead of silently substituting another policy. **Save reflection** persists the student's observation, interpretation and next change linked to the exact report and policy hash. **Review improvement draft** retrieves the parent's exact project and training recipe, copies the proposed change into an explicitly unsaved draft, and retains the parent reflection identity. Opening the draft removes the prior individual-duck training banner without changing the group roster or stopping training. Reviewing or reloading a reflection never saves or starts another trial and does not warm-start policy weights.

<a id="multiple-ducks"></a>

## Multiple ducks

Robot Studio's **Your dance group** starts with one duck. Add, duplicate, rename and remove members, retaining at least one. Each duck has its own **Policy** dropdown and saved **Training project** selection. Duplicating copies those selections, not policy weights or a training run. Line, Grid and Circle formations with editable spacing place recordings on the stage; they do not change simulation starting conditions or model collisions.

**Set up individual training** loads the selected saved project into Micro Duck's **Train** subtab and identifies the duck being edited; open the Micro Duck tab to continue. Save an edited project draft first. Training remains a manual, per-duck use of existing trials: start a trial, wait for its exported policy, then assign that policy to the duck in Studio. Selecting a policy does not fine-tune it; there is no group training queue or checkpoint warm start. Parallel environments train one policy, not several duck policies.

**Record group dance** captures the roster, names, policy assignments and placements before any requests. `LabClient` simulates every selected policy sequentially with the same requested horizon, reset seed and zero command, verifies the returned policy identity/hash and playable duration, then publishes all tracks together. A missing or incompatible selection prevents recording; a failed request preserves the prior recording rather than publishing a partial group. Replay is explicit: every duck shares one start and playback clock and stops at the shortest recorded duration.

The first recorded duck's matching run supplies its frozen project soundtrack when present; current training-project selections cannot replace it. Other duck policies are not retimed to match its BPM. **Motion details** selects an individual recorded duck. Roster, assignment, name and formation edits leave the loaded group unchanged until another recording succeeds. Independent rollouts do not model inter-duck collisions or learned coordination. The [group playback decision](../../../.agents/notes/implemented/feature/2026-09-05-microduck-independent-group-playback.md) records why synchronized presentation is separate from joint physics.

**Save group file** downloads `duck-dance-group.json`; **Load group file** restores its version-1 roster. The JSON object contains `version: 1`, `members`, `formation` and `spacing`. Each member contains `id`, `name`, `policyId`, `projectRevisionId`, `x` and `z`; the file embeds no ONNX policies, projects or recordings. Load in the originating session to resolve session-owned artifacts. Missing policy/project references remain visible as **Unavailable policy** or **Unavailable revision**, never silently reassigned; choose available replacements before recording or setting up the affected training project.

Files are limited to 1 MiB and 1–`maxGroupMembers` members. Loading validates JSON/version, unique positive integer member IDs, nonblank bounded names, nullable bounded references, supported formation, spacing and finite stage coordinates before replacing the roster draft. Invalid files leave the draft unchanged. A successful load does not start training or playback, and the prior recording remains unchanged until re-recording succeeds.

<a id="shared-playback-and-music"></a>

## Shared playback and music

One `LabClient` and one `PlaybackTransport` capture each session identity. The React-free client owns projects, run records, polling, scene data and recordings; the entry-declared store owns drafts, selection and viewing preferences. Both center controls and the right player bind those same owners. Switching conversations never retargets requests. Closing the player releases its renderer and pauses playback, but does not cancel server-owned training. Clients remain resident until plugin disposal; disposal stops polling, ignores late responses, detaches listeners and closes owned audio resources without claiming to abort an admitted server operation.

Music is original local percussion, bass and melody in Disco, Electronic, Lo-fi or Chiptune styles. Version, style, BPM, beats and seed form the persisted recipe. PCM and downloadable mono PCM16 WAV bytes are generated client-side and are not persisted by DSH. No music account, provider key, voices or commercial recordings are used. **Generate music (WAV)** downloads without autoplay; temporary download URLs are revoked.

Playback is explicit and non-looping. **Replay speed** selects 0.5×, 1×, 1.5× or 2× and remains a per-session preference. It scales shared logical recording time and audio playback together; audio tempo and pitch change, without pitch preservation. Generated PCM/WAV, recipe BPM, training and measured physics remain unchanged. Changing rate during pending audio resume cancels the pending start and leaves playback paused.

With music, `AudioContext.currentTime` is the master time for both sound and pose; only an explicit `music: null` uses the monotonic silent clock. Audio unavailability or failed resume leaves playback paused with an error; **Play without music** is an explicit choice, not a silent fallback. Pause, seek, restart, recording replacement, document/view hiding, session switch, recording end and disposal synchronize sound and pose. **Restart** returns to zero and plays; seeking preserves active playback unless it reaches the end or cancels a pending audio resume. Muting changes gain, not time. A fall can shorten the recording; sound stops with it rather than looping or extending the motion.

The r3f stage opens with an orbitable Studio grid before scene assets or a performance are loaded; it neither invents robot poses nor starts simulation or playback. Empty-stage guidance and **Preview standing policy** sit below the grid. Loaded recordings render backend meshes and timestamped frames with pose-based camera framing, lighting and ground shadows. Camera presets, Reset view, Expand view, canvas-scoped orbit controls and focused Space playback affect presentation only. Studio grid, Concrete, Sand and Grass are flat visual appearances, not terrain or friction settings. Clicking a part opens its recorded world position. **Motion details** distinguishes actual ordered joint positions/velocities, controller targets, actuator torques, root speed and tilt from kinematic target values; foot contacts are not recorded. **Routine tempo** is saved BPM; **Body speed** is measured per recorded second, not multiplied by replay speed. Average training steps/second is a separate throughput metric. The current block/beat indicator uses the recording's frozen block sequence and logical time, never the current draft.

<a id="model-experience"></a>

## Model Experience

### Native studio presentation

#### What the model sees

SequenceByAI sends one ordinary logged user prompt containing the quoted activity, request identity, installed model fingerprint, ordered joint limits/defaults, optional matching hinge metadata and strict output instructions. The prompt instructs the current agent to load `microduck-choreography`, plan a timed guide and return it with matching motion in one correlated final JSON envelope. This package registers no model tool; the [Robot Lab bundle](../../bundle/robot-lab/README.md) supplies the skill independently of the session's working directory. Other direct controls call `robotLab.request`; service-owned records and separate tool results determine their session history.

#### Token effect

Each SequenceByAI gesture adds its prompt, skill load, generated guide and keyframes to the current session's token usage. Rendering, playback and music generation add no model tokens. Meshes, per-frame transforms and PCM are excluded from prompts.

#### KV Cache effect

Generation extends the current conversation through normal prompt admission; provider cache behavior remains owned by the configured model and session pipeline. The plugin creates no separate model request channel or cache.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- Target previews are forward kinematics, and policy playback is recorded physics; neither is live robot telemetry or interactive motor control. No learned dance is established by setup tests, a training completion label or upright/termination criteria.
- Clip Gen pose editing and MP4 capture provide visual references only. Calibrated choreography presets, uneven-terrain physics, cloud training and verified physical deployment are not provided. Local custom-clip policies remain simulation-only.
- Duck rosters, names, policy/project assignments and formations are transient per-session view state. They survive closing and reopening the Studio tab, not browser refresh; export a group file before refreshing and load it afterward. Unexported group edits, loaded group recordings and transient PCM are lost on refresh; [authoring draft recovery](#authoring-draft-recovery) applies separately. A group file preserves references, not their artifacts; retain saved project revisions and complete experiment directories to reproduce recordings.
